# Roadmap

Planned work, in priority order.

## 1. Notes ("micro obsidian")

Markdown notes stored in SQLite, written in Obsidian-compatible markdown so notes export as plain `.md`. Built in chunks, each its own branch and PR:

1. **Notes core** — done, see Done below
2. **Read view and copy as HTML** — done, see Done below
3. **Search** — done, see Done below
4. **Linking** — done, see Done below
5. **Folders** — done, see Done below
6. **Semantic search** — done, see Done below
7. **Chat that edits notes** — deferred; local model with tool calls proposing diffs to accept or reject

## 2. JS playground

A `/playground` page with an editor, Run (⌘↵) and a console pane; nothing is persisted. Needs a sandbox, because code in the main WebView could reach the database through IPC: `rquickjs` (pure JS, fully isolated, new cargo dependency) or a sandboxed iframe (browser APIs, but needs a CSP/IPC isolation spike first). Basic scope and globals completion comes almost free; full TypeScript IntelliSense is optional (~1–2 days). JSON notes can be passed in as variables through an input picker (JSON notes now exist).

## 3. JSONC

Comments (and trailing commas) in JSON notes; today they show as lint errors and Format refuses them. Findings from a spike on the current dependencies:

- `@lezer/json` has no comment syntax: `//`, `/* */` and trailing commas parse as error nodes, so lint, Format and Minify (which refuse error nodes) reject them.
- `@codemirror/language-data` has no `jsonc` entry and maps `json5` to plain JSON, so neither gives comment support.
- `@codemirror/legacy-modes` (a transitive dependency) has a `json` stream mode that tokenizes `//` and `/* */` comments correctly. Highlighting is therefore possible through `StreamLanguage` (a new direct dependency), but a stream mode gives no syntax tree, so there would be no tree-based lint, folding or Format.
- Lossless JSONC formatting needs a JSONC parser (a new dependency, for example `jsonc-parser`), because custom parsers are ruled out. ```` ```jsonc ```` and ```` ```json5 ```` blocks in markdown notes are not formatted either, for the same reason.

## 4. Release pipeline hardening

`release.yml` publishes a release on every `v*` tag push without running the gates. Add a gate job (`cargo test`, `cargo clippy --all -- -D warnings`, `cargo fmt --check`, `npm run check`, `npm run lint`, `node --test tests/*.mjs`) that the release job `needs:`; pin third-party actions (`actions/*`, `dtolnay/rust-toolchain`, `swatinem/rust-cache`, `tauri-apps/tauri-action`) to commit SHAs; default the workflow to `permissions: contents: read` and grant `contents: write` only to the release job.

## 5. Dependency monitoring

Dependabot for npm, cargo and GitHub Actions (grouped weekly updates), plus a `cargo deny check advisories` (or `cargo audit`) step and `npm audit --omit=dev` in the gate job.

## 6. Major dependency upgrades

Each on its own branch: `sqlx` 0.9, `sha2` 0.11, `tokenizers` 0.23 first; then `typescript` 7, `prettier-plugin-svelte` 4, `@types/node` 26 and `tailwind-merge` 3; Tailwind 4 last (touches all styling and `app.css`).

## Done

- JSON notes — a note or the scratchpad can be switched between markdown and JSON (header toggle, or "Switch to JSON" / "Switch to Markdown" in the note context menu; the body is never rewritten, new notes start as markdown); JSON mode is a code editor with highlighting, folding, bracket matching and closing, and a lint gutter showing the first parse error, without live preview, `#`/`[[` completion or the slash menu, and ⌘E and Copy as HTML are hidden; Format and Minify are lossless (a printer over the Lezer JSON syntax tree that copies number, string and key text verbatim, so big integers, `1.0`, escapes and duplicate keys survive; 2-space indent; invalid JSON is refused with "Invalid JSON: line L, col C"); bodies are capped at 5 MB (markdown is not); JSON notes are title-only in search, have no tags or links and are never embedded, show no excerpt, and carry a "JSON" badge in the tree, search list and ⌘K; in markdown editors (notes, scratchpad, handovers) a ```` ```json ```` block gets Format and Minify chips on its fence line while the cursor is inside it, and ⇧⌥F formats the block; stored in a `Kind` column on `notes` and `scratchpad`, with a `kind` field in backups (older backups restore as markdown); `@codemirror/lang-json` and `@codemirror/lint` are direct dependencies
- Encrypted backups — one automatic backup folder, `backups/` beside the database by default or any writable folder (iCloud Drive, Dropbox) picked in Settings; flat `badger-YYYY-MM-DD.json.gz` files, only files matching that name are listed, trimmed or deleted, and old dated-folder backups are left alone; optional `age` encryption (`.json.gz.age`, decrypts with `age -d … | gunzip`) with a generated key pair whose secret is shown once and must be pasted back before encryption turns on, or your own `age1…` key; restore asks for the secret key for encrypted files; Back up now, last success and last error in Settings, no fallback to another folder or to plaintext when a backup fails; "Delete unencrypted" after turning encryption on; `age` is a direct dependency
- Notes performance — measured on a mocked 5,000-line note (built SPA in headless Chromium, keystroke → editor update settled, p50/p95 over 120 samples, 108 for opening): typing 15.9/26.6 ms → 6.6/11.5 ms and opening a note 27.7/38.3 ms → 19.6/25.9 ms; arrow-key moves were already within the 16 ms budget (5.3/11.5 ms) and stay there. The live-preview link decorations now scan only the visible lines for tags and wikilinks (`extractRefs` takes ranges) instead of the whole note on every keystroke, and the reference-definition walk is skipped for notes without `]:`. The old premise was stale: `list_notes` already returns excerpts, not bodies, and takes ~23 ms for 2,000 notes; `update_note_body` on a 5,000-line note takes ~14 ms (optimized build, `#[ignore]`d `perf_*` tests in `commands/notes.rs`), so the backend is unchanged. Deferring `doc.toString()` (~0.1 ms per keystroke) and range-limiting the `blocks.ts` walk (~1.3 ms) were not needed
- Gzipped backups — automatic backups are written as `backups/YYYY-MM-DD/backup.json.gz` (atomic) and manual export defaults to `badger-backup-<date>.json.gz`; the content is still the same JSON (`gunzip -c` reads it), so it stays readable and compatible through `#[serde(default)]`. Restore detects gzip from the leading bytes (`1f 8b`) and otherwise reads plain JSON, so old `.json` backups still restore; listing and trim accept either name. Measured ~3–6× smaller on synthetic data (notes-heavy ≈3×, record-heavy ≈6×); `flate2` is a direct dependency
- Handover notes — a short end-of-day markdown note to your future self: write it in a "Today's handover" card on Today (the notes live-preview editor, autosaved and flushed on quit; emptying it deletes it) or with the ⌘K "Write handover" action; the next working day (Mon–Fri, no holidays; Friday to Sunday show on Monday) the newest earlier handover appears as a read-only card on Today, just above the editor, whose task checkboxes still tick and persist, with Dismiss, ←/→ to browse every past handover (dismissed included) and "Save as note" (a root note `Handover YYYY-MM-DD`, indexed; the handover stays); task checkboxes in every editor are now keyboard-focusable (Space/Enter); kept out of notes search, links and the semantic index; stored in a `handovers` table (one row per local date) included in backup/restore (older backups restore with none)
- Scratchpad — one persistent pad for throwaway text in a left slide-over drawer on every page, opened with ⌘J, the ⌘K "Scratchpad" action or the icon beside Settings; the notes live-preview editor with autosave (flushed on close and quit); "Save as note" asks for a title and turns the whole pad into an indexed root note, plus Copy as HTML, a ⌘E read view and Clear; kept out of notes search, links and the semantic index; stored in a single-row `scratchpad` table included in backup/restore (older backups restore with an empty pad); the Settings shortcut recorder rejects ⌘J
- Badger — the app is now called Badger (bundle id `io.github.narvallabs.badger`, data in `~/.badger/`, dev data in `.badger-dev/`) with a badger app icon generated from `src-tauri/icons/icon-source.png`
- Reminders — Slack-style one-off or recurring pings (daily, weekdays, weekly on chosen days, monthly) at an exact local time, created by typing `remind call Anna in 20 min` (English or Swedish) in ⌘K with a live preview, from the `/reminders` page, from a todo, or from a note's context menu; due ones become native macOS notifications (batched when several fire at once, skipped while the window is focused) and actionable in-app toasts with Done and Snooze, with the fired count on the dock badge; managed on `/reminders` (Overdue / Today / Tomorrow / Later / Done) and a Today card; stored in `reminders` and included in backup/restore. Fires only while the app runs; the missed ones fire as a catch-up on launch
- Notes semantic search — opt-in in Settings › Preferences (downloads a ~350 MB multilingual Granite embedding model on click, then indexes your notes in the background); the notes list and ⌘K merge meaning-based hits into the keyword results (Reciprocal Rank Fusion), marked "related" when the note has no keyword match, so a Swedish query finds English notes and vice versa; search stays keyword-only until the model is ready; the index is derived, not in backups, and rebuilt after restore
- Notes folders — the notes list is a folder tree (folders first, then notes pinned first; order within each group is manual, set by dragging between rows or ⌥↑/⌥↓); create, rename (pencil or F2) and delete folders inline, deleting moves the contents to the parent; move notes and folders by pointer drag and drop (collapsed folders auto-expand under the pointer, Esc cancels) or with a keyboard "Move to…" picker; right-click (Ctrl+click, Shift+F10) a row for a context menu with its actions; ⌘N, `+` and followed unresolved wikilinks create in the current folder; search hits show their folder path; arrow-key navigation (↑/↓, ←/→, Enter/Space, F2), and expanded folders are remembered
- Notes linking — Obsidian-style `#tags` and `[[wikilinks]]` (`[[Title]]`, `[[Title|alias]]`) with `#` and `[[` autocomplete; `#acme`, `#acme/website`, `#issue/<id>` and `#todo/<id>` link to customers, projects, issues and todos, the last two shown as chips with the live title (todo chips coloured by status); ⌘-click in the editor or a plain click in the read view follows a link, a tag filters the note list, and following an unresolved wikilink creates the note; `#term` in the note search or ⌘K filters by tag (nested: `#acme` also matches `#acme/website`); a "Linked mentions" strip lists backlinks; renaming a note, customer or project rewrites matching links and tags in all notes, and deleting leaves a plain tag or an unresolved link
- Notes search — SQLite FTS5 (`trigram`: case-insensitive substrings, so `rapport` finds `tidrapport`; å/ä/ö stay distinct) over titles and plain-text bodies; the note list ranks by relevance (title hits first) with highlighted titles and snippets, ⌘K lists the top 5 notes (from 3 typed characters), and Settings › Preferences shows the index size with a Rebuild button
- Notes read view — ⌘E toggles a read view rendered in Rust (`pulldown-cmark`; raw HTML escaped, only http/https/mailto links, images never load) with highlighted code and links that open in the browser; "Copy as HTML" puts rendered HTML and the markdown source on the clipboard
- Notes core — `/notes` page with a filtered note list and a CodeMirror 6 editor with Obsidian-style live preview (headings, emphasis, code, quotes, lists, task checkboxes, tables), autosave, pinning, ⌘N and a palette "New note" action; `notes` and nestable `folders` tables included in backup/restore; a quit/close guard flushes unsaved edits
- Today — start page at `/` with todos needing attention, in-progress todos, today's logged time and a Mon–Sun week strip with progress against a daily hours target (Settings › Preferences); the Timesheet moved to `/timesheet` and gained a Single Day filter
- Command palette — ⌘K (configurable in Settings) for navigation, New todo and a keyboard-only Log time flow (project → issue → hours/date → notes) that remembers the last project and issue
- Restore overwrites only — merge mode removed; restore always replaces all data with the backup
- SvelteKit 3 — Kit 3, Vite 8, vite-plugin-svelte 7, adapter-static 4; config moved into `vite.config.ts`, `$lib` → `#lib`, `$app/stores` → `$app/state`
- Travel — `/travel` page (date, from/to, optional km and kr; add, edit, repeat, delete) and the month's travel plus a copy-as-text export on the monthly report
- Dark mode — System/Light/Dark in Settings › Preferences, persisted in `app_settings`, no flash on startup
- Edit customers and projects — inline rename with name validation, and a grouped-card layout in Settings
